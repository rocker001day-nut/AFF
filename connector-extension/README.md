# AFF Account Connector 0.1 — session capture prototype

## ติดตั้งใน Chrome หรือ Edge
1. แตก ZIP ไว้ในโฟลเดอร์ถาวร
2. เปิด chrome://extensions หรือ edge://extensions
3. เปิด Developer mode แล้วเลือก Load unpacked / โหลดส่วนขยายที่คลายการแพ็ก
4. เลือกโฟลเดอร์ที่มี manifest.json
5. เปิด https://aff-lyart.vercel.app/ ในเบราว์เซอร์เดียวกัน ล็อกอิน AFF แล้วรีโหลดหน้าเว็บ
6. Auto Sync → เพิ่มบัญชีจริง → กด “เชื่อม / รับเซสชันใหม่”
7. เปิดแพลตฟอร์ม ล็อกอิน แล้วกลับมายืนยันชื่อ/รหัสบัญชีในหน้าต่างส่วนขยาย
8. อนุญาตสิทธิ์คุกกี้เฉพาะแพลตฟอร์มที่เลือก แล้วกดรับเซสชัน

รองรับหลาย snapshot แยกด้วย user ID และ account ID ของ AFF ใน chrome.storage.session ซึ่ง content scripts อ่านไม่ได้ การปิดเบราว์เซอร์ทั้งหมด/ปิดส่วนขยายจะล้าง snapshot และต้องรับใหม่ ห้ามนำโฟลเดอร์โปรไฟล์หรือคุกกี้ไปใส่ GitHub

## ขอบเขตที่ทำแล้วและยังไม่เสร็จ
- รับคุกกี้ใหม่เมื่อผู้ใช้กดเอง และแทนที่เฉพาะบัญชี AFF ที่ระบุ
- ค่าคุกกี้ไม่ส่งเข้าเว็บ AFF หรือเซิร์ฟเวอร์ ส่งกลับเพียงสถานะการรับและจำนวนคุกกี้
- ไม่แตะรหัสผ่าน ไม่ข้าม OTP/CAPTCHA ไม่แก้คุกกี้ในเบราว์เซอร์
- โปรไฟล์เบราว์เซอร์มีบัญชีแพลตฟอร์มปัจจุบันเพียงชุดเดียว: ผู้ใช้ต้องสลับบัญชีแล้วตรวจชื่อให้ตรงก่อนรับ snapshot ถัดไป ส่วนขยายยังไม่ตรวจ account identity กับเซิร์ฟเวอร์แพลตฟอร์ม
- **ยังไม่มีตัวดึงรายงานหรือการส่งยอดเข้า AFF อัตโนมัติ** การรับคุกกี้ไม่เท่ากับเชื่อมดึงรายงานสำเร็จ ต้องติดตั้งและทดสอบเซสชันจริงก่อนพัฒนาตัวอ่านข้อมูลแต่ละแพลตฟอร์มต่อ
- ยังไม่ทดสอบติดตั้งส่วนขยายจริงในเครื่องผู้ใช้ ทดสอบ logic ด้วย mock API เท่านั้น

## Permissions
`storage` ใช้เก็บ snapshot ใน RAM ของส่วนขยาย; `cookies` และ host permission ขอเมื่อกดรับเซสชัน เฉพาะ *.shopee.co.th หรือ *.lazada.co.th เนื่องจากล็อกอินและ Affiliate Portal ใช้ subdomain ต่างกัน สิทธิ์นี้เข้าถึงคุกกี้ล็อกอินที่อาจใช้แทนการเข้าบัญชีได้
Content script ทำงานเฉพาะ https://aff-lyart.vercel.app/ ไม่มี endpoint ส่งออกคุกกี้ และไม่ติดตามคุกกี้เบื้องหลัง

ทดสอบ: `node --test tests/connector.test.js` จากราก AFF-main
